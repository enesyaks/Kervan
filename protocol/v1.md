# Kervan protocol v1

Mac app ↔ server. Server code: `server/src/protocol.ts`. Mac code: `mac/Sources/KervanKit/Protocol.swift`.
Both must change together; bump `PROTOCOL_VERSION` on any breaking change.

## Transport

- WebSocket at `ws://<host>:7420/v1/ws` (Tailscale only, so no TLS at this layer).
- Auth: `Authorization: Bearer <token>` header on the upgrade request.
  Wrong or missing token → HTTP `401` before the upgrade, no socket is opened.
- One JSON object per text frame. Every message has a `type`.
  Requests that expect a reply carry an `id` (client-chosen string); the reply echoes it.
- Server sends WebSocket ping frames every 30 s and drops clients that don't pong.

## Handshake

The client's first message must be `hello`. Until then the server answers everything else with
`error` / `hello_required`.

```json
→ {"type":"hello","protocol":1,"client":{"name":"Kervan for Mac","version":"0.1.0"}}
← {"type":"welcome","protocol":1,"server":{"name":"kervan","version":"0.1.0"},"agents":["claude"]}
```

After `welcome` the client receives every `session.updated` and `session.event` broadcast, for all sessions.

If `protocol` is not supported the server replies `error` / `unsupported_protocol` and closes with code `4000`.

## Messages

### Client → server

| type              | fields                                        | reply |
|-------------------|-----------------------------------------------|-------|
| `hello`           | `protocol: number`, `client: {name, version}` | `welcome` |
| `ping`            | `id`                                          | `pong` |
| `session.create`  | `id`, `agent`                                 | `session.created` (status `starting`) |
| `session.list`    | `id`                                          | `session.list.result` |
| `session.history` | `id`, `sessionId`                             | `session.history.result` |
| `session.prompt`  | `id`, `sessionId`, `text` (1–100 000 chars), `attachments?: string[]` (≤ 20 workspace paths) | `ok`, then events |
| `session.cancel`  | `id`, `sessionId`                             | `ok`; open permission requests resolve as `cancelled` |
| `session.permission` | `id`, `sessionId`, `requestId`, `optionId` (one of the request's options) | `ok` |
| `session.rename`  | `id`, `sessionId`, `title` (1–120 chars)      | `ok`, then `session.updated` |
| `session.archive` | `id`, `sessionId`, `archived: boolean`        | `ok`, then `session.updated` |
| `session.search`  | `id`, `query`                                 | `session.search.result` |

### Server → client

| type                     | fields                                                      |
|--------------------------|-------------------------------------------------------------|
| `welcome`                | `protocol`, `server: {name, version}`, `agents: string[]`   |
| `pong` / `ok`            | `id`                                                        |
| `error`                  | `code`, `message`, `id?` (the failed request's id, also for malformed requests that carry one) |
| `session.created`        | `id`, `session: SessionInfo`                                |
| `session.list.result`    | `id`, `sessions: SessionInfo[]`                             |
| `session.history.result` | `id`, `sessionId`, `events: SessionEvent[]`                 |
| `session.updated`        | `session: SessionInfo` (broadcast)                          |
| `session.event`          | `sessionId`, `event: SessionEvent` (broadcast)              |
| `session.search.result`  | `id`, `hits: [{sessionId, seq, role: user\|agent, snippet}]` (best first, ≤ 50) |

`SessionInfo`: `{id, agent, title, status, createdAt, archived, error?}`; `status` is `starting | idle | running | waiting | error | closed`; `waiting` means a permission request is open.
Only `idle` sessions accept a prompt.

`SessionEvent`: `{seq, at, kind, ...}` — `seq` starts at 1 per session and has no gaps.

| kind                       | fields                                         |
|----------------------------|------------------------------------------------|
| `user_message`             | `text`, `attachments?`                          |
| `agent_message_chunk`      | `text` (append to the current agent message)   |
| `agent_thought_chunk`      | `text`                                         |
| `tool_call`                | `toolCallId`, `title`, `toolKind`, `status`    |
| `tool_call_update`         | `toolCallId`, `title?`, `status?`              |
| `permission_request`       | `requestId`, `title`, `toolKind`, `detail?`, `options: [{optionId, name, kind}]` |
| `permission_resolved`      | `requestId`, `outcome: selected \| cancelled`, `optionId?` |
| `turn_end`                 | `stopReason` (ACP reasons, plus `interrupted` when a server restart cut the turn off) |
| `notice`                   | `text` — something Kervan did, e.g. resuming the agent |
| `error`                    | `message`                                      |

Clients must ignore event kinds they don't know.

### Error codes

| code                   | meaning                                  |
|------------------------|------------------------------------------|
| `bad_message`          | frame is not a JSON object with a string `type`, or fields are missing |
| `unknown_type`         | `type` is not defined in this version    |
| `hello_required`       | a message arrived before `hello`         |
| `unsupported_protocol` | `hello.protocol` is not supported        |
| `unknown_agent`        | `session.create` named an agent the server doesn't have |
| `unknown_session`      | no session with that id                  |
| `session_busy`         | the agent is still answering the previous prompt |
| `session_unavailable`  | the session is starting, errored or closed |
| `unknown_request`      | no open permission request with that id  |

Clients must ignore server message types they don't know, so the server can add types without a version bump.

A `permission_request` without a later `permission_resolved` for the same `requestId` is still open:
the agent waits, however long the user is away. `kind` of an option is `allow_once | allow_always | reject_once | reject_always`.

## Persistence

Sessions and events are stored in SQLite (`$KERVAN_DATA_DIR/kervan.db`). After a server restart every session
is listed again with its full history; an interrupted turn ends with `turn_end`/`interrupted`, open permission
requests resolve as `cancelled`, and the next prompt resumes the same agent conversation (ACP `session/resume`).

## Files (HTTP)

Same host and port, same `Authorization: Bearer <token>` header. Paths are workspace-relative, `/`-separated,
each segment URL-encoded. Absolute paths, `..` and symlinks leading out of the workspace are refused with `400`.

| request | result |
|---|---|
| `GET /v1/sessions/:id/files` | `200 {entries: [{path, type: file\|dir, size, modifiedAt}], truncated}` — skips `.git`, `node_modules`; at most 5000 entries |
| `GET /v1/sessions/:id/files/<path>` | `200` file bytes (`application/octet-stream`) |
| `PUT /v1/sessions/:id/files/<path>` | `201 {path, size}`; body is the raw file; parents are created; `413` above `KERVAN_MAX_UPLOAD_MB` (default 512) |

Errors: `401` bad token, `404` unknown session or file, `400` bad path. Attachments in `session.prompt` reach the
agent as ACP `resource_link` blocks with `file://` URIs; uploading first and then attaching is the client's job.

## Search

Whole messages are indexed (an agent's streamed chunks are joined). Every query word must match, as a word prefix.
Matching ignores case and Turkish/Latin diacritics, and treats `ı`, `İ`, `I` as `i`, so `rotasi` finds `rotası`.
`seq` is the first event of the matched message — the same id the client uses for that transcript row. In `snippet`
(≈120 chars of the original text) each match is wrapped in `\u0001` … `\u0002`.
